# App Flow Document for Sirko

## Onboarding and Sign-In/Sign-Up
When a user first arrives at the Sirko application, they land on a welcome page that briefly explains the core features of the multi-branch POS system and offers clear buttons for signing in or registering a new account. A brand-new user who needs access clicks on the Register link and is taken to a form where they provide their name, the email address associated with their branch, and a secure password. After submitting this information, an email confirmation is sent. Once the user clicks the confirmation link, they are able to log in.

Existing users click the Sign In button on the welcome page, which takes them to a login form requesting email and password. Upon entering valid credentials, the application authenticates the user against the backend via a JWT-based flow and redirects them to their appropriate dashboard. A forgot-password link on the login form leads to a password recovery page where the user enters their email. The system sends a one-time reset link that, when clicked, opens a page to set a new password. After resetting, the user can return to the login form. At any point after signing in, the user can choose to sign out by clicking the Logout option in the sidebar, which clears the session token and brings them back to the welcome page.

## Main Dashboard or Home Page
Upon successful login, the user lands on the main dashboard, which adapts based on their role. Cashiers see the POS interface by default, showing a product search bar at the top, a live shopping cart on the right, and a numeric keypad below. Managers land on an overview tile that highlights today’s sales totals, low-stock alerts, and a quick link to start a stock opname. Owners arrive at a summary of branch performance that displays total revenue across all locations, recent profit figures, and buttons to navigate to branch management and user administration.

The dashboard features a vertical sidebar on the left with branded styling. The sidebar entries vary by role but always include Home, Settings, and Logout. Cashiers have quick access to POS and Sales History. Managers have links to Inventory, Stock Opname, Sales History, and Reports. Owners additionally see Branch Management and User Management. A header bar at the top shows the currently selected branch and a dropdown that allows switching branches if the user has access to more than one location.

## Detailed Feature Flows and Page Transitions
When a cashier begins a sale, they type or scan a product code into the search field and hit Enter. The item appears in the cart panel with default quantity one. The cashier can tap the quantity number to open a small overlay for adjusting the count or click a remove icon to delete an item. When ready, the cashier clicks the Pay button, which opens a payment modal showing total amount and fields for payment type. After confirming payment, the system runs an atomic transaction in the backend that decrements stock, creates a sales record, and returns a receipt object. The UI then displays the receipt in a printable view with options to print or email it, and the cart resets to empty.

A manager who needs to adjust stock navigates to the Inventory page by clicking its link in the sidebar. This page loads a paginated table of products and their variants, showing current stock for the active branch. The manager can filter by product name or SKU using a search input, then click a product row to open a detail modal. Inside the modal, they can manually change the stock level and save. Behind the scenes, an API call updates the branch_stock table and returns the new quantity, which refreshes the table view.

To perform a full stock opname, the manager clicks the Stock Opname link in the sidebar. They see a list of all items and text fields beside each for entering counted quantities. After filling in counts, they press the Submit button at the bottom. The page makes a single API request that wraps all updates in a database transaction, ensuring recorded stock matches the physical count. Once complete, the interface displays a confirmation message and a summary of changes.

Sales history is accessible from any role by selecting Sales History in the sidebar. The page shows a date picker for selecting a range and a dynamic table listing each transaction with time, products sold, total amount, and cashier name. Clicking a row opens a detail drawer on the right, offering a full breakdown of items, taxes, and payment method. Managers and owners can use this view to investigate specific transactions.

Owners who need to see high-level performance go to Reports. This page presents date selectors and report type options such as daily sales trends or monthly profit. After choosing parameters, the owner clicks Generate and the page renders interactive charts and tables. A Download CSV link under each report triggers export of the underlying data in a portable format.

Branch management is available only to owners via the Branch Management link. On this page, the owner sees a list of existing branches with their addresses and status. The owner clicks New Branch to open a form for entering branch name, location details, and assigning a time zone. After saving, the new branch appears in the list and can be selected in the header dropdown by users who have been granted access.

User management lives alongside branch management for owners. The owner clicks User Management in the sidebar to view a table of users, their assigned role, and branch. The owner can click Invite User, which opens a form to enter an email address, select role, and pick a branch. Upon submission, the system sends an invitation email with a secure link. When the invite is accepted, the new user sets a password and is immediately able to log in with permissions defined by the owner.

## Settings and Account Management
Every user can customize their own account by clicking Settings in the sidebar. This opens the Account Settings page, which has fields for updating name, email, and password. Beneath these fields, there is a section for notification preferences where the user can toggle email alerts for low-stock warnings or daily sales summaries. After making changes, the user clicks Save, and the application confirms success. A link at the top of the page returns the user to the main dashboard for their role.

## Error States and Alternate Paths
If a user enters incorrect credentials on the login page, a red error message appears under the form explaining that the email or password is invalid. During registration or password reset, if the email address is not found or is already in use, the form shows a clear validation error next to the email field. When the app loses network connectivity, a dismissible banner appears at the top of every page warning of offline mode and disabling form submissions until the connection is restored. If a user tries to access a page they are not authorized for, the app redirects them to a 403 Unauthorized page that explains they lack the needed permissions. Any unexpected server error during API calls surfaces as a generic error dialog with a Retry button. Clicking Retry reattempts the request or, if the issue persists, offers to return to the home dashboard.

## Conclusion and Overall App Journey
A typical journey in Sirko begins with a user registering or logging in and landing on a role-specific dashboard. Cashiers proceed to the POS screen to scan items and complete sales, managers move between inventory adjustments and stock opname tasks, and owners oversee branch operations, user invitations, and business analytics. Throughout the flow, clear navigation, immediate feedback, and consistent error handling guide users from start to finish. Whether the goal is to finalize a quick sale, reconcile stock counts, or generate a comprehensive sales report, Sirko delivers a seamless path from the first click to the final confirmation.
